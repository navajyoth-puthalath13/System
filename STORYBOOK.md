# Storybook

An **additional, interactive layer** over the existing design system — for developing,
documenting, and visually testing components. It does **not** replace the documentation
showcase (`public/`), the shadcn registry (`public/registry/`), the machine-readable map
(`registry/`), the tokens, or the `npm run build` pipeline. Those are untouched and keep
working exactly as before.

Storybook renders the **real** React components from `components/` using the **existing**
Tailwind v4 pipeline (`postcss.config.mjs`) and tokens (`src/index.css`). There is no second
token system and no component is reimplemented for Storybook.

## Commands

```bash
npm run storybook          # dev server on http://localhost:6006
npm run build-storybook    # static production build → storybook-static/
```

`npm run build` is unchanged — Storybook is intentionally **not** part of it.

## How it reuses the design system

- **Components** — stories import `components/button/button.tsx` directly.
- **Tokens galleries** — `foundations/*.stories.tsx` render a **Tokens/** section (Colors,
  Typography, Spacing, Elevation, Border) from the token JSON (`tokens/`) using the live CSS
  variables, so they stay in sync with the source of truth and react to the theme toolbar.
  They document tokens only; they do not redefine any.
- **Tokens / CSS / Tailwind** — `.storybook/preview.ts` imports `src/index.css` (the single
  source of truth: `@import "tailwindcss"` + every primitive and semantic token). Vite picks
  up the existing `postcss.config.mjs` automatically, so the token-backed utilities
  (`bg-action-primary`, `text-text-inverse`, `shadow-sm`, …) compile exactly as in a consuming
  app.
- **Path alias** — `.storybook/main.ts` mirrors the tsconfig `@/* → src/*` alias so
  `@/lib/utils` resolves identically.
- **Dark / light** — the theme toolbar toggles the existing `.dark` class, which flips the
  token values defined in `src/index.css`.

## Addons

- `@storybook/addon-docs` — autodocs (component API from args/argTypes).
- `@storybook/addon-a11y` — accessibility (axe) inspection of the real component.
- `storybook-addon-pseudo-states` — demonstrates the `:hover` / `:focus-visible` / `:active`
  states the Button defines, without reimplementing them.

The existing `components/button/button.mdx` is **not** ingested by Storybook — it remains part
of the design-system documentation architecture. Only `*.stories.*` files are collected.

## Deploying as a separate Vercel project

The two sites share one GitHub repository but are **separate Vercel projects** that do not
interfere:

| Project | Build command | Output directory | Config |
| --- | --- | --- | --- |
| Design system (existing) | `npm run build` | `public` | `vercel.json` |
| Storybook (new) | `npm run build-storybook` | `storybook-static` | project settings |

For the Storybook project, in its **Vercel Project Settings** set:

- **Build Command:** `npm run build-storybook`
- **Output Directory:** `storybook-static`

Vercel project-level settings override the repo `vercel.json`, so the existing design-system
project keeps using `vercel.json` (`npm run build` → `public`) untouched. `storybook-static/`
is git-ignored and regenerated by the build.
